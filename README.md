# Формула

Внутреннее веб-приложение для расчета себестоимости изделий из эпоксидной смолы.

## Стек

- Frontend: статический SPA для GitHub Pages.
- Backend: Supabase Auth, Database, Storage.
- 3D: Three.js.

## Supabase

- Project ref: `hapgpphyucjciiinwlbx`
- URL: `https://hapgpphyucjciiinwlbx.supabase.co`
- Publishable key: лежит в `src/config.js`
- Storage bucket: `epoxy-photos`

Секретные ключи в проект не добавляются. Доступ к данным закрыт через Supabase Auth и RLS.

## Локальный запуск

```bash
python3 -m http.server 4173
```

После запуска открыть:

```text
http://localhost:4173
```

## Разделы MVP

- Авторизация.
- Материалы и склад.
- Приходы и ручные корректировки.
- Готовые изделия и состав из сохраненных расчетов смолы.
- Продажи, логистика и учет готовой продукции.
- Автоматическое списание материалов после фиксации партии.
- История расчетов и движений склада.
- Расчет смолы на молд.

## Инструменты и ресурс

Во вкладке «Склад → Инструменты» хранятся модели и отдельные физические экземпляры.
У каждого экземпляра свои цена, остаток ресурса и история. Ресурс можно учитывать
по изделиям, заливкам, часам работы или календарному сроку службы. Для заливок
задается число изделий за цикл; неполная заливка тоже расходует один цикл.
Календарный срок продолжает идти на паузе. Стоимость календарного инструмента
распределяется по времени работы изделия и числу рабочих часов в день.

В карте изделия выбираются инструменты или общий набор мастерской. Карта показывает
плановую стоимость по настройкам модели. Кнопка «Изготовить» предлагает два шага:
количество, затем проверку реальных экземпляров и фактических затрат. Только
подтверждение списывает материалы и ресурс, фиксирует затраты и приход продукции.
Продажи и возвраты ресурс повторно не списывают. Добавление уже готового остатка
без изготовления остается отдельным действием.

Износ не превышает стоимость покупки. Продление ресурса распределяет оставшуюся
неучтенную стоимость; уже полностью учтенный инструмент не оплачивается повторно.
Списание сохраняет нераспределенный остаток стоимости отдельным событием истории.
Исторические материалы типа «Молд / инструмент» сохранены: их модели перенесены
в инструменты, но ресурс и фактическое количество требуется подтвердить вручную.
В расчетах «Смола» остаются только расходные материалы.

## Проверки

```bash
node --test tests/equipment.test.mjs
node --check src/main.js
node --check src/equipment.js
```

`tests/equipment-ui.mjs` проверяет формы, черновики, фильтры и адаптивность через
Playwright с полностью подмененным backend. Перед запуском нужен локальный HTTP
сервер на порту 4174. Можно задать `APP_URL`, `PLAYWRIGHT_MODULE`, `BROWSER_PATH`
и `LUCIDE_FILE`. Снимки сохраняются в `/tmp/formula-equipment-ui`.

`tests/equipment-database.sql` проверяет атомарность, повтор запроса, разные цены
экземпляров, ресурс и RLS внутри транзакции с финальным `ROLLBACK`. Выполняется
администратором БД на тестовом окружении с примененной миграцией
`supabase/migrations/20260915192957_equipment_inventory.sql` и существующей схемой
приложения. Файл миграции дополняет рабочую схему, а не создает ее с нуля.
